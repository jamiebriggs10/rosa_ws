## What broke, and the fix

- **Parakeet MLX native streaming dropped and garbled words.** "move the tool over the inspection plate" → "Move the the inspection plate."; the pause clip lost "move left" entirely; one setting (look-ahead 64, 320 ms chunks) returned "". A sweep of look-ahead × chunk size showed only look-ahead 256 + 640 ms chunks got both test clips right. Fix: new defaults (`context_right` 256, `stream_chunk_ms` 640) plus a `final_pass` knob (default on). The stream gives the live partials; the final text comes from one batch pass (~30–40 ms). `final_pass: false` keeps pure streaming for the comparison.
- **Parakeet re-contacted Hugging Face on every load** (`snapshot_download` each time), so it wouldn't have loaded offline. Fix: one folder per model under `models/parakeet-mlx/`, download only if `config.json` is missing.
- **bfloat16 audio broke parakeet-mlx's `get_logmel`** (sub-agent finding). Fix: compute the mel from float32, then cast to bfloat16.
- **whisper-server left running** after switching engine, and after `kill`ing the app. Cause: replaced plug-ins were never closed; SIGTERM skips Python's `atexit`. Fix: the pipeline calls `close()` on a plug-in it replaces; `app.py` turns SIGTERM into a normal exit. Verified live (server gone after switching away and after kill).
- **Page looked empty in a headless screenshot.** Not a bug: the screenshot was taken before the data loaded. Still made `/events` send `: connected` at once, so the browser's `open` (which triggers the data load) fires immediately rather than at the first event. Checked with Chrome DevTools: no JS errors, all panels filled.
- **pywhispercpp rejects `initial_prompt=None`** (TypeError). Fix: only pass it when the prompt is non-empty.
- **WebRTC VAD `reset()` didn't reset**: `set_mode` keeps the noise estimate. Fix: make a new `Vad` object.
- **Moonshine in batch mode hallucinated** on the synthetic clips: a leading "you" on most clips, invented tails ("Move down 10 cm to the left."), "stop" → "Stay tuned for more". The output changes with the amount of silence around the speech, so it's the model, not our plumbing. Its native streaming mode is far better (WER 4.5 % vs 41 %). Added `presets/moonshine-streaming.yaml`.
- My own pipeline tests first failed on arithmetic (1.0 s ≠ a whole number of 32 ms frames) and a fake VAD with no `min_speech_ms`. Tests now count in frames.
- Headless Chrome with `--virtual-time-budget` hangs forever on a page with an open SSE stream; used the DevTools protocol from a small node script instead.

Wake word (wake-jarvis): 40/40 synthetic wake clips detected (100 %), median wake delay ≈ 0 ms after the end of "hey Jarvis", 0 false wake-ups in ≈ 8 min of synthetic noise (too little audio to quote a per-hour rate with any confidence).

Full table (more columns): `results/2026-10-08-synthetic.md` / `.csv`; raw records: `runs/2026-10-08-*-synthetic.jsonl`.

Reading it (synthetic, so provisional):
- With a button, everything except faster-whisper on the CPU is well under the 1 s target; Parakeet MLX batch is fastest and joint-most-accurate of the fast engines.
- Hands-free endpointing is the real cost: the silence timeout *is* the felt delay. On these clips (every pause exactly 1.0 s) silence ≤ 700 ms cut every pause clip; Smart Turn was the fastest hands-free option (253 ms) but still cut 77.5 % of pause clips, and on TTS voices it can't tell complete from incomplete. Needs real speech.
- Command accuracy is lower than WER suggests on the endpoint presets because a cut-off command loses its number/unit: that's the safety-relevant error.

Other measured numbers: Silero 0.08 ms / frame, WebRTC 0.005 ms, openWakeWord 1.4 ms per 80 ms, Smart Turn ~9 ms per check, Parakeet MLX load ~1–2 s (+0.3–0.5 s warm-up). The first utterance after starting the app took ~200–400 ms to transcribe (later ones ~30 ms): probably MLX compiling for a new audio length. Not a thread problem (measured: worker and main thread both ~28 ms warm).

## Learned

- Every engine writes digits and mostly US spelling or abbreviations ("5", "centimeters", "cm"); Whisper glues coordinates ("x10y-60z70"). The console will need the same normalising that `bench/score.py` does.
- Parakeet ignores the prompt (no-prompt preset = identical results). It heard **"halt" as "Hold."** for all four voices and "freeze" as "Phrase" for two. That matters for the planned stop shortcut (docs/06): the stop words list may need "hold", or the stop check should use a separate small keyword model.
- Native streaming isn't automatically better: Parakeet MLX's was worse than batch on accuracy; Moonshine's was much better than its batch mode.
- Synthetic speech is too regular for endpointing experiments (identical 1.0 s pauses, falling pitch at every phrase end). Real recordings are essential for experiment 1.
- The adaptive rule "Move left." = complete is wrong for this domain: a direction with no amount usually means more is coming. Candidate rule for the dissertation.
- Durable facts copied into `docs/02-options.md` (*Built:* notes), `docs/04` (extra endpoints), `docs/05` (synthetic set, how presses are simulated).
