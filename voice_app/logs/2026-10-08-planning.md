# 2026-10-08 — planning the voice prototype

**Goal:** decide the architecture and options for the voice front end, set up this folder.
**Result:** worked (plan and docs, no code yet)

## What was done
- Looked through `../fyp-cobot/` (read only) to see what voice will plug into: a Flask console (`rosa_ws/web_console.py`, port 8000) with `POST /command` and `POST /stop`.
- Researched options for each stage (wake word, VAD, end of turn, speech-to-text) and how "real-time" dictation works (streaming vs batch).
- Created this folder: `CLAUDE.md`, `README.md`, `docs/01`–`06` + glossary, `settings.yaml`, `requirements/`, `stages/base.py` (the stage contract), test-set script in `bench/testset/commands.csv`, build brief.

## Decisions
- Separate prototype folder; `fyp-cobot` not touched. Python + Flask, matching the console so they can merge later.
- Four swappable stages (trigger, VAD, end of turn, speech-to-text) behind one small interface each; options chosen in a settings page.
- Both wake word (openWakeWord) and push-to-talk. Porcupine ruled out (free tier ended June 2026).
- Speech-to-text options: Parakeet (first), whisper.cpp, faster-whisper, Moonshine; each in streaming and batch mode.
- End of turn options: silence timeout, adaptive (our own rules on the partial text), Smart Turn v3, PTT release.
- Mac now, NVIDIA Linux PC later: plug-ins hide the hardware, `device: auto`, separate requirements files.
- Benchmark by replaying a fixed recorded test set through any settings; command accuracy (numbers, units, directions) as well as WER.

## Learned
- The console's LLM step is ~6.5–8 s to motion, so the voice front end (~0.3–1 s) won't dominate total delay; endpointing and the stop shortcut are where voice speed matters most.
- Wispr Flow's dictation is cloud-processed; Wispr hasn't published how the new notetaker transcribes. Its live transcript suggests streaming, but that isn't confirmed.
