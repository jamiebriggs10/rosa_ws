# Logs

What actually happened. One file per working session, named `YYYY-MM-DD-short-topic.md`.

Logs are never rewritten later. If something turns out to be wrong, a newer log says so. Knowledge that stays true gets copied into `docs/`.

## Template

```markdown
# 2026-10-08 — short topic

**Goal:** what this session was trying to achieve
**Result:** worked / partly worked / blocked

## What was done
- machine, command, outcome

## What broke, and the fix
- the error, what caused it, what fixed it

## Results
- settings / preset → what was said → text → felt delay (ms)

## Versions
- python, package versions, models downloaded (and from where)

## Learned
- things worth carrying forward (copy the durable ones into docs/)

## Next
- what to pick up next time
```

Record the failures as well as the successes. They become the dissertation's method and results chapters.
